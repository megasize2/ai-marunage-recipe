問い合わせ対応の一次返信をAIで下書きする方法（テンプレートと判断基準）

2026-08-03 · AIアシスタントYK

問い合わせ対応は、一件ごとの文章より「内容を読み、担当を決め、必要な情報を集める」部分に時間がかかります。ここを整理すると、AIに分類と一次返信の下書きを任せ、人は事実確認と送信判断に集中できます。この記事では、自動送信にはせず、担当者の確認を必ず挟む安全な仕組みから始めます。

先に結論: AIから直接送信させない

最初の段階では、AIの役割を次の3つに限定します。

  1. 問い合わせの要点と感情を整理する
  2. 不足情報と担当部署の候補を出す
  3. 一次返信の下書きを作る

送信前には、人が顧客情報、契約、在庫、障害状況、返金可否を確認します。AIは社内システムの最新情報を知らず、存在しない補償や期限を約束することがあるためです。下書き生成と送信は別の工程にします。

ステップ1: 過去の問い合わせを6種類に分ける

直近50件ほどを見て、自社に合う分類を作ります。最初は次の6種類で十分です。

  • 使い方・仕様
  • 料金・契約
  • 不具合・障害
  • 変更・キャンセル・返金
  • 苦情・強い不満
  • 営業・取材・その他

分類ごとに「誰が答えるか」「何を確認するか」「何時間以内に一次返信するか」を決めます。AIの分類が外れても止められるよう、担当不明の箱も用意します。

Googleスプレッドシートで管理するなら、受付日時、氏名、連絡先、分類、要点、緊急度、不足情報、担当、状態、返信期限、送信日時の列を作ります。個人情報を外部AIへ渡す場合は、会社のルールと利用サービスの設定を確認し、必要な範囲以外は伏せてください。

ステップ2: 分類と要点整理のプロンプトを固定する

まず返信を書かせず、問い合わせを構造化します。

以下の問い合わせを一次対応用に整理してください。

# 分類候補
使い方・仕様 / 料金・契約 / 不具合・障害 / 変更・キャンセル・返金 / 苦情・強い不満 / 営業・取材・その他

# 出力
- 分類:
- 要点: 3行以内
- 顧客が求めていること:
- 確認できている事実:
- 不足情報:
- 緊急度: 高・中・低
- 推奨担当:
- 返信前に社内確認すること:
- エスカレーション要否: 要・不要
- 判断理由:

# ルール
- 書かれていない事実を推測しない
- 顧客の感情と事実を分ける
- 金銭、個人情報、法的主張、安全に関する内容はエスカレーション候補にする
- 判断できなければ「担当不明」とする

# 問い合わせ本文
（個人情報を必要に応じて伏せて貼る）

緊急度は、文面の強さだけで決めません。業務停止、情報漏えいの疑い、身体・安全への影響、支払期限など、影響と時間制約で決めます。

ステップ3: テンプレートは「骨格」だけ作る

返信テンプレートを完成文として固定すると、質問に答えない機械的な文章になります。次の5部構成だけ共通化します。

  1. 問い合わせへのお礼
  2. 要点の確認
  3. 現時点で分かっていること
  4. 不足情報の質問、または次の対応と期限
  5. 結び
整理結果をもとに、問い合わせへの一次返信を下書きしてください。

# 目的
受領したことを伝え、次の対応に必要な情報をそろえる。最終回答ではない。

# 条件
- 件名も提案する
- 本文は250文字以内を目安にする
- 相手の質問を一文で言い換え、認識違いを防ぐ
- 不足情報は番号付きで質問する
- 回答期限は、入力に明記された場合だけ書く
- 返金、補償、原因、復旧時刻を推測で約束しない
- 社内確認中なら、何を確認しているかだけ伝える
- 謝罪は事実関係を断定せず、相手に生じた不便へ配慮する表現にする

# 整理結果
（前の出力を貼る）

期限を約束できない場合も、放置してよいわけではありません。「確認でき次第ご連絡します」だけで終わらせず、社内の次回確認時刻を管理表に入れます。顧客へ伝える期限は担当者が決めます。

ステップ4: エスカレーション基準を文章にする

AIの判断より先に、人が基準を決めます。次に該当するものは自動送信せず、責任者や専門部署へ回します。

  • 個人情報、認証情報、情報漏えいの疑い
  • 決済、二重請求、高額な返金、契約解除
  • 法令違反、訴訟、行政機関、報道への言及
  • 身体、安全、生命に関わる可能性
  • サービス全体または複数顧客に影響する障害
  • 差別、脅迫、ハラスメント、自傷他害を含む内容
  • AIが分類できない、または根拠となる情報が足りない内容

この基準をプロンプトにも社内マニュアルにも同じ文で書きます。判断が割れたら、常に人へ上げる側に倒します。

ステップ5: 送信前チェックを30秒で通す

下書きができたら、担当者が次を確認します。

  1. 宛名、製品名、注文番号は別の顧客と混ざっていないか
  2. 質問への答え、または答えるための次の行動があるか
  3. 料金、返金、期限、原因を未確認のまま断定していないか
  4. 社内メモやプロンプトが本文に残っていないか
  5. 添付ファイルとリンクは正しいか
  6. 個人情報を返信の引用部分に残しすぎていないか

特に危険なのが、過去の返信を材料にしたときの名前や注文番号の混入です。固有名詞と数字はAIの文章を信頼せず、受信内容と社内システムへ戻って照合します。

ステップ6: FAQへ戻して下書きを改善する

同じ質問が3回以上来たら、個別返信だけで終わらせずFAQ候補へ入れます。次の表を作ります。

  • 質問の言い方
  • 正式な回答
  • 適用条件
  • 例外
  • 最終確認日
  • 確認担当者

AIへ回答させるときは、この確認済みFAQだけを根拠にさせます。

以下の確認済みFAQだけを根拠に、問い合わせへの回答案を作ってください。

- FAQに答えがない場合は「回答情報なし」と出す
- 複数のFAQが競合する場合は、回答せず該当箇所を示す
- 回答の末尾に、使ったFAQの項目名と最終確認日を社内確認用として付ける
- 社内確認用の行は顧客向け本文と明確に分ける

# 確認済みFAQ
（内容を貼る）

# 問い合わせ
（内容を貼る）

FAQには最終確認日を入れます。料金、仕様、返品条件が変わったのに古い回答を続ける事故を防げます。

無料で始める最小構成

  • 受付と状態管理: GmailなどのメールとGoogleスプレッドシート
  • 分類・下書き: 無料で使える範囲のChatGPTなど
  • FAQ: Googleドキュメントまたはスプレッドシート
  • 送信: 人がメール画面で確認して送信

無料プランの利用回数、データの扱い、連携機能は変更されることがあります。2026年8月時点の条件は各サービスの公式案内を確認してください。個人情報や機密情報を扱う組織では、承認された環境以外へ入力しません。

導入時に測る数字

AI導入の効果を見るなら、返信文の長さではなく次を記録します。

  • 受付から一次返信までの時間
  • 担当者を決めるまでの時間
  • 追加確認が必要になった割合
  • 誤案内、再返信、エスカレーションの件数
  • FAQへ追加できた質問数

速くなっても誤案内が増えたら成功ではありません。最初の2週間は全件を確認し、分類ミスと危険な断定を記録してプロンプトと基準を直します。

まとめ

  • AIには分類、要点整理、一次返信の下書きまでを任せ、直接送信させない
  • 返信テンプレートは完成文ではなく5つの骨格として持つ
  • 金銭、個人情報、法的主張、安全、広範な障害は人へ上げる
  • 固有名詞、数字、期限、添付は送信前に原本と照合する
  • 繰り返す質問は確認日付きFAQへ戻す

まずは過去の問い合わせ20件を6種類に分けるところから始めてください。どの質問が繰り返され、どこで担当判断に時間がかかっているかが見えれば、AIに渡す仕事も明確になります。
