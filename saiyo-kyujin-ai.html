求人票と面接質問をAIで作る方法（応募者に伝わる原稿を短時間で準備）

2026-08-09 · AIアシスタントYK

求人票を書くために過去原稿をコピーし、「明るい人」「若手が活躍」のような言葉だけ変える——これでは仕事の実態が伝わらず、表現上の問題も残ります。AIを使うと白紙からの作成は速くなりますが、採用条件をAIに決めさせてはいけません。この記事では、現場から事実を集め、求人原稿、NG表現の確認、面接質問と評価表まで作る手順を解説します。

先に集める: 自社紹介より仕事の事実

AIへ「魅力的な求人票を書いて」と頼む前に、次を現場の責任者へ確認します。

  1. 入社後90日で任せる仕事
  2. 1日の流れと、週・月単位の定例業務
  3. 必須条件と、入社後に学べる条件
  4. 一緒に働く人数、報告先、関係部署
  5. 働く場所、時間、休日、雇用形態、報酬
  6. 評価される成果と、仕事の難しい点

「コミュニケーション能力」のような抽象語は、実際の行動へ直します。たとえば「顧客の要望を聞き、社内の開発担当へ文章で共有する」です。

会社の採用ページや過去求人をAIへ渡す場合は、現在も正しい情報だけにします。古い福利厚生や出社方針が混ざると、そのまま誤掲載されます。

ステップ1: 事実メモから求人票の初稿を作る

決まっていない項目は空欄のまま渡します。AIに推測させず、確認事項として返させます。

以下の事実から求人票の初稿を作ってください。書かれていない条件を推測で追加しないでください。

# 募集情報
- 職種: 法人向けカスタマーサポート
- 雇用形態: 正社員
- 勤務地: 東京都内。週2日まで在宅勤務可
- 勤務時間: 9:30〜18:30
- 休日・給与・試用期間: （ここに正式情報を入れる）

# 実際の仕事
- メールとオンライン会議で法人顧客の問い合わせに対応
- 問い合わせ内容を開発チームへ記録・共有
- 毎週、よくある質問を更新
- 入社後30日は過去事例と製品を学び、60日目から担当顧客を持つ

# 条件
- 必須: 法人顧客とのメール対応経験、基本的な表計算
- 歓迎: SaaSのサポート経験、業務マニュアル作成経験
- 入社後に学べる: 製品知識、問い合わせ分析

# チームと評価
- 5人チーム、報告先はサポート責任者
- 評価: 初回返信の速さだけでなく、解決率とFAQ改善への貢献
- 難しい点: 顧客ごとに利用環境が異なり、関係部署との確認が必要

# 出力
- 仕事の要約
- 具体的な業務内容
- 入社後30・60・90日のイメージ
- 必須条件 / 歓迎条件
- この仕事で得られる経験
- チーム体制
- 応募前に知ってほしい難しさ
- 募集要項
- 不足情報の確認リスト

# 文体
- 誇張せず、応募者が働く場面を想像できる具体的な日本語
- 「アットホーム」「やりがいのある仕事」など根拠のない決まり文句は使わない

初稿が返ったら、不足情報リストを人が埋めます。待遇や就業条件は、社内の正式な募集条件と一致させます。

ステップ2: 必須条件を減らして応募の入口を整える

現場は「あれば安心」な経験をすべて必須へ入れがちです。しかし、入社後に学べるものまで必須にすると候補者を狭めます。

各条件を次の3つに分けます。

  • 初日から必要: 法令上の資格、すぐ担当する業務の経験など
  • あると立ち上がりが速い: 歓迎条件へ移す
  • 入社後に学べる: 求人票では研修・成長機会として書く

AIには「この必須条件が、どの業務に必要か対応表にして」と頼みます。対応する仕事がない条件は、採用チームで削れるか検討します。

ステップ3: NG表現と誤解を招く表現を点検する

求人広告には、年齢・性別などに関する不適切な限定、実態と異なる条件、根拠のない優位表現を入れないよう注意が必要です。掲載媒体の審査基準もあります。AIは見落とし候補の洗い出しに使い、最終確認は最新の法令、行政の案内、掲載媒体の規定、必要に応じて専門家を優先します。

以下の求人票を、応募者の誤解と不適切な表現を減らす観点で点検してください。

# 確認する観点
- 年齢、性別、国籍、家族状況などを不必要に限定・示唆していないか
- 「若手」「男性向き」「主婦歓迎」など、属性で役割を決める表現がないか
- 必須条件と歓迎条件が混ざっていないか
- 給与、勤務場所、勤務時間、雇用形態が曖昧でないか
- 「業界No.1」「必ず成長」など、根拠を確認できない表現がないか
- 仕事の良い面だけでなく、難しさも書かれているか

# 出力
- 該当箇所
- 問題になりうる理由
- 事実を保った修正案
- 人事または専門家へ確認すべき点

# 条件
- 法的に問題ないと断定しない
- 原稿にない会社情報を追加しない

（ここに求人票を貼る）

たとえば「若手が活躍」は、伝えたい事実が年齢なのか、裁量なのか、研修なのかを考えます。「入社年次に関係なく改善提案を担当できる」など、確認できる行動へ書き換えます。

ステップ4: 面接質問を職務から逆算する

面接で聞くべきなのは、話の上手さではなく、仕事に必要な行動の再現性です。求人票の業務と評価項目から質問を作ります。

以下の求人票をもとに、45分の構造化面接を準備してください。

# 評価したい項目
- 顧客の要望を正確に整理する力
- 関係部署へ必要情報を共有する力
- 未知の製品を学ぶ力
- FAQや手順を改善する力

# 出力
各項目について次を作る
1. 全候補者へ同じように聞ける主質問
2. 事実を深掘りする追加質問を2つ
3. 良い回答に含まれる行動例
4. 注意して確認する回答
5. 1〜5点の評価基準

# 条件
- 過去の具体的な行動を聞く質問にする
- 家族、結婚、出産、思想信条など、職務と関係ない個人情報は質問しない
- 圧迫的な言い方にしない
- 候補者からの質問時間を10分確保する

# 求人票
（完成した求人票を貼る）

「あなたの長所は」だけで終わらず、「難しい問い合わせを受けたとき、何を確認し、誰へ共有し、結果はどうなったか」と過去の行動を聞きます。

ステップ5: 質問と評価表を全候補者で揃える

候補者ごとに質問が違うと比較が難しくなります。主質問と評価基準は共通にし、深掘りだけ回答に合わせます。評価表には次を置きます。

  • 評価項目
  • 回答の事実メモ
  • 1〜5点
  • 点数の根拠
  • 追加確認が必要な点

面接直後に、印象ではなく発言事実を書きます。AIへ面接メモを渡して整理する場合は、候補者本人の個人情報や社内の採用データを入力してよい環境か確認し、必要最小限にします。採否の決定をAIへ丸投げせず、人が職務との対応を説明できる状態にします。

運用で効く3つのルール

1. 求人票の責任者と更新日を残す

働き方や待遇が変わっても、古い原稿が再利用されがちです。原稿の末尾または管理表に責任者と最終確認日を残します。

2. 現場社員に5分だけ読んでもらう

同じ職種の社員へ「実際と違う点」「応募前に知るべき点」を聞きます。魅力を足すより、入社後の驚きを減らす方が大切です。

3. 面接後に質問の有効性を見直す

全員が同じ模範回答になる質問は、評価材料になりません。具体的な行動を聞けたかを振り返り、次回の深掘り質問を直します。

まとめ

  • 自社の宣伝文ではなく、仕事・条件・評価の事実を先に集める
  • AIには不足情報を推測させず、確認リストとして返させる
  • 必須条件を初日から必要なものへ絞り、NG表現候補を点検する
  • 面接質問と評価基準を職務から逆算し、全候補者で主質問を揃える

まず現場責任者へ「入社後90日で任せたい仕事」を3つ聞いてください。その答えが、求人票にも面接にも使える一番強い材料になります。
