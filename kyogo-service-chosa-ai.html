競合サービス調査をAIで効率化する方法（比較表を作るプロンプト付き）

2026-08-10 · AIアシスタントYK

競合調査で時間がかかるのは、検索そのものより、各社で表現の違う料金や機能を同じ基準へそろえる作業です。AIを使えば整理は速くなりますが、「競合3社を比較して」とだけ頼むと、古い料金や推測がもっともらしく混ざります。この記事では、調査項目を先に固定し、出典を残し、人が原文を確認するところまでを一つの手順にします。

先に決める: AIは調査員ではなく整理役

AIに任せる範囲は、次の3つです。

  1. 調査項目と検索語のたたき台を作る
  2. 公式ページから集めた情報を同じ形式へそろえる
  3. 比較表から違いと追加調査事項を抽出する

最終的な事実確認と評価は人が行います。Web検索機能のないAIは、今の料金や機能を確認できません。検索できるAIでも、古いページや第三者の記事を参照することがあります。URLが付いた回答も、正しいとは限りません。

ステップ1: 調査の目的を一文で決める

最初に「何の判断に使うか」を書きます。目的が違えば、見る項目も変わるからです。

  • 自社サービスの改善: 機能、対象顧客、訴求、サポートを重視
  • 導入先の選定: 料金、契約条件、セキュリティ、運用負荷を重視
  • 営業資料の準備: 違いが説明できる根拠と適用条件を重視

今回は「社内で導入する問い合わせ管理サービスを3社から選ぶ」という例で進めます。社名を挙げる前に、必須条件と比較項目をAIに点検させます。

問い合わせ管理サービス3社を比較するため、調査項目を設計してください。

# 調査の目的
従業員50人の会社で、メールとWebフォームの問い合わせを5人で管理するサービスを選ぶ

# 必須条件
- 複数担当者で対応状況を共有できる
- 日本語で利用できる
- 月額費用を確認できる

# 出力
- 比較すべき項目
- 各項目を確認する理由
- 公式サイト内で探すページ
- 検索に使う語句
- 判断に不要な項目

# ルール
- 製品名や機能を推測で追加しない
- 「あると便利」と「選定に必須」を分ける
- 比較項目は12個以内に絞る

項目を増やしすぎると、調べても判断に使わない表ができます。目的に関係しない項目はここで削ります。

ステップ2: 情報源の優先順位を固定する

調査は、各社の公式サイトを優先します。見る順番を決めておくと、AIが拾った情報の信頼度を判断しやすくなります。

  1. 公式の料金・機能・セキュリティ・利用規約ページ
  2. 公式ヘルプ、公式のお知らせ、公式資料
  3. 官公庁や認証機関など、内容を直接確認できるページ
  4. 比較サイト、口コミ、個人ブログ

4は使用感を知る補助にはなりますが、料金や仕様の確定には使いません。「公式資料に見つからない」と「機能がない」も別です。見つからない場合は、表へ「記載なし」ではなく確認不能と入れます。

検索機能付きのAIを使う場合は、次のプロンプトを1社ずつ実行します。3社を一度に頼むより、出典の混線を減らせます。

次のサービスについて、指定項目を調査してください。

# 対象サービス
（会社名・サービス名・公式サイトURL）

# 調査項目
- 最安の有料プランと月額料金
- 課金単位（1人、1契約、従量など）
- 初期費用
- 無料試用の有無
- メールとWebフォームの受付
- 担当者の割り当てと対応状況の管理
- 権限管理
- データの保存・セキュリティに関する公開情報
- サポート窓口
- 最低契約期間と解約条件

# 出力形式
| 項目 | 確認できた内容 | 適用条件・注記 | 出典URL | ページの更新日または確認日 |

# 調査ルール
- 公式サイト、公式ヘルプ、公式規約を優先する
- 料金は税込・税別、月払い・年払いを区別する
- ページに書かれていない内容を推測しない
- 情報が見つからなければ「確認不能」と書く
- 出典URLは項目ごとに付ける
- 同じ項目で記載が食い違う場合は両方を示す
- 最後に「人が追加確認すべき点」を列挙する

Web検索が使えないAIでは、このプロンプトだけで調査はできません。その場合は、自分で公式ページを開き、必要な箇所とURLをコピーして次の工程へ進みます。

ステップ3: 公式ページの内容を同じ型へそろえる

料金表やヘルプの文章をAIへ渡し、比較できる形に整えます。全文を大量に貼るより、該当箇所とURLをセットで渡す方が確認しやすくなります。

以下は3サービスの公式ページから抜き出した情報です。比較表に整理してください。

# 比較表の列
サービス名 / 料金 / 課金単位 / 初期費用 / 無料試用 / 受付方法 / 担当管理 / 権限管理 / セキュリティ / サポート / 契約条件 / 確認日

# ルール
- 入力にある事実だけを使う
- 条件付きの機能は、条件を省略しない
- 税別と税込、月払いと年払いを勝手に換算しない
- 「無料」と「無料試用」を区別する
- 比較できない項目は「条件が異なる」と書く
- 不明なセルは「要確認」とする
- 各セルの末尾に対応する出典番号を付ける
- 表の後に、各社へ問い合わせる質問を作る

# 情報
## サービスA
[A1] URL: （URL）
確認日: （YYYY-MM-DD）
抜粋・メモ: （公式ページで確認した内容）

## サービスB
[B1] URL: （URL）
確認日: （YYYY-MM-DD）
抜粋・メモ: （公式ページで確認した内容）

## サービスC
[C1] URL: （URL）
確認日: （YYYY-MM-DD）
抜粋・メモ: （公式ページで確認した内容）

ここで重要なのは、単純な丸付けにしないことです。たとえば「権限管理あり」でも、管理者と一般利用者の2種類だけなのか、部署単位まで設定できるのかで意味が変わります。条件は注記として残します。

ステップ4: 比較表から判断材料を作る

表が埋まったら、AIに順位を決めさせる前に評価基準を作ります。料金だけで選ぶなら簡単ですが、機能や運用負荷を含めると、会社ごとに重要度が違います。

以下の比較表を、導入担当者の意思決定用に整理してください。

# 評価基準と重み
- 必須条件を満たすか: 40点
- 5人で使う場合の費用を確認できるか: 25点
- 権限と対応状況を管理しやすいか: 20点
- 導入・移行の負担: 10点
- サポート: 5点

# 出力
1. 必須条件を満たさない候補
2. 各社の点数と根拠
3. 各社が向いている条件
4. 点数を変える可能性がある未確認事項
5. 無料試用で確認する操作を5つ

# ルール
- 比較表に根拠がない項目は0点にせず「採点保留」とする
- 好みで点数を補わない
- 費用は確認できる条件だけで計算式を示す
- 最終的な推奨は、未確認事項を解消した後に出す

# 比較表
（前の工程で作った表を貼る）

「確認不能」を0点にすると、情報公開が少ない会社を自動的に不利にしてしまいます。採点保留にして、問い合わせや無料試用で埋める方が公平です。

つまずきやすいポイント3つ

1. AIが存在しない料金プランを補う

よくある名前の「スタンダード」「ビジネス」などを、AIが別サービスの記憶から混ぜることがあります。料金、プラン名、最低利用人数は必ず公式料金ページへ戻って確認します。料金が「要問い合わせ」なら、推定額は入れません。

2. 同じ機能名でも範囲が違う

「自動化」「分析」「AI対応」のような言葉は、そのままでは比較できません。何を入力し、何が実行され、誰が確認するのかまで分解します。機能名ではなく、自社で行いたい操作が完了するかを無料試用で確かめます。

3. 比較表の確認日が消える

料金と仕様は変わります。表にはURLだけでなく確認日を残し、社外向け資料へ使う直前に再確認します。利用規約、個人情報、セキュリティ、解約条件は、AIの要約だけで判断せず原文を読みます。法務や情報システム部門の確認が必要な会社では、その手順を優先してください。

まとめ

  • 調査前に目的と比較項目を固定し、項目は12個以内に絞る
  • 公式ページを優先し、出典URLと確認日を項目ごとに残す
  • 見つからない情報は推測せず「確認不能」「要確認」とする
  • 条件の違う料金や機能を無理に同じ尺度へ直さない
  • 最後は問い合わせと無料試用で、未確認事項を人が埋める

まずは候補を3社に絞り、ステップ1のプロンプトで比較項目を作ってください。調査の型を一度作れば、次回は社名と目的を入れ替えるだけで同じ基準を使えます。
